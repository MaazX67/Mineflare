# Contributing to Mineflare

Thank you for your interest in contributing to Mineflare! This document provides guidelines and instructions for contributing.

## Code of Conduct

- Be respectful and inclusive
- Focus on code quality and maintainability
- Help others and share knowledge
- Report issues responsibly

## Getting Started

1. Fork the repository
2. Clone your fork: `git clone https://github.com/YOUR_USERNAME/Mineflare.git`
3. Create a feature branch: `git checkout -b feature/your-feature-name`
4. Install dependencies: `npm install`
5. Make your changes
6. Run tests: `npm test`
7. Commit your changes: `git commit -am 'Add your feature'`
8. Push to the branch: `git push origin feature/your-feature-name`
9. Submit a Pull Request

## Code Standards

### JavaScript
- Use ES6+ syntax
- Use async/await for asynchronous code
- Document public methods with JSDoc
- Use descriptive variable names

### Formatting
- Run `npm run format` to format code
- Run `npm run lint:fix` to fix linting issues
- Max line length: 100 characters

### Commits
- Use clear, descriptive commit messages
- Reference issues: "Fix #123"
- Keep commits atomic and focused

## Pull Request Process

1. Ensure your code follows the style guide
2. Update documentation as needed
3. Add tests for new features
4. Ensure all tests pass
5. Fill out the PR template completely
6. Be responsive to review feedback

## Reporting Issues

- Check if the issue already exists
- Provide a clear, descriptive title
- Include steps to reproduce
- Specify your environment (Node version, OS, etc.)
- Attach logs or screenshots if applicable

## Feature Requests

- Use a clear, descriptive title
- Describe the desired behavior
- Explain why this feature would be useful
- Include examples if possible

## Documentation

When adding new features:

1. Add JSDoc comments to functions
2. Update README if adding user-facing features
3. Add examples to demonstrate usage
4. Keep documentation up to date

## Testing

- Write tests for new features
- Ensure all tests pass before submitting PR
- Aim for good test coverage
- Test edge cases and error scenarios

## Questions?

Feel free to open a discussion or issue if you have questions!

Thank you for contributing to Mineflare! 🎮
